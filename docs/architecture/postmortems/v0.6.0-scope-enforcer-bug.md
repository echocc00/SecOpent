# Postmortem: v0.6.0 升级失败 — ScopeEnforcer 平行 matcher 拒绝 HTTP-prefixed scope (v9/v9.5)

> **日期**: 2026-08-13（事故 14:00-20:25 +0800, NAS 部署;上游修复同日落 v0.6.1）
> **影响**: 绿联 NAS DXP4800PLUS 上 v0.5.3 → v0.6.0 升级后,任何 `http(s)://` 形式的 scope 评估在 `_check_plan_scope` 被拒(1 秒内 failed,无扫描容器);回滚 v0.5.3 后同 scope 形式复现值完全相同(同一 bug)
> **严重度**: High(升级边界核心功能不可用,数据/模式无损——`control` 列为 additive nullable)
> **事故报告**: operator 侧 postmortem(issue v9.5);本文为代码侧核实 + 修复 + 防回归
> **状态**: 修复已发布 **v0.6.1**(commit `c082e5f`);防回归 R1(e2e)/R2(linter R4)随本文件落地

---

## 1. 根因(代码核实)

**单一职责的双份实现失同步**:

- `ScopeSnapshot._target_matches`(domain,唯一真源)在 **v0.5.3** 修复了 HTTP-prefixed 分支(issue v8 Fix A,commit `c57afe2`)。
- `ScopeEnforcer._host_matches_rule`(application,私有复制,自 v0.5.0 commit `025ceda` 引入 `ScopeEnforcer` 时就存在)**从未**有 HTTP 分支:URL rule 落到 `host == rule` 恒 False。

于是:
- `scope.includes_ip("192.168.2.18")`(domain,egress_guard 路径)→ True
- `ScopeEnforcer.check("http://192.168.2.18:3000", ...)`(executor `_check_plan_scope` 路径)→ `NOT_INCLUDED`

`_check_plan_scope`([application/execution.py](src/secopent/application/execution.py))以 `scope.include` 条目为目标逐一过 `enforcer.check` → 所有 URL-form scope 的评估在**扫描容器启动前**被拒,审计只看到 `assessment.blocked.scope_violation`(payload `NOT_INCLUDED`)。

**判定**: 实现问题(修复只打了一侧)为主;两 matcher 并存的结构是设计遗留(职责重复)。修复采用消除拷贝而非打补丁。

## 2. 为什么单测没抓到

- `ScopeSnapshot` 的 URL-rule 测试在 v0.5.3 已加(`test_includes_ip_matches_http_prefixed_ip_rule`)。
- `ScopeEnforcer` 的测试([tests/security/test_scope_enforcer.py](tests/security/test_scope_enforcer.py))全部用 bare-host/CIDR scope(如 `"192.168.2.18"`/`"10.0.0.0/30"`)——恰好不经过 URL 分支。
- 现实主义 tier(realism)覆盖的是审计/outbox 持久性与并发,不触碰 scope-enforcement 路径。
- `execute_assessment` 的既有测试大多**不传 scope_enforcer**(None → 检查直接跳过),或传了但 scope 是 CIDR。

三处覆盖盲区叠加 → v0.6.0 全量门禁绿,HTTP-scope 依然全挂。

## 3. 修复(v0.6.1,commit `c082e5f`)

**Fix B——删除平行 matcher,统一委托 domain**:

- [domain/scope/models.py](src/secopent/domain/scope/models.py):新增公开 `matches_any(host, rules)` / `includes_host(host)` / `excludes_host(host)`,全部基于 `_target_matches`(唯一的 host↔rule 匹配实现)。
- [application/scope_enforcer.py](src/secopent/application/scope_enforcer.py):删除 `_host_matches_rule`;`check` 步骤 2/3 改为 `scope.excludes_host(host)` / `scope.includes_host(host)`。

行为矩阵(回归测试钉死):URL-IP rule + URL/bare-IP target ALLOWED、URL exclude 优先、外来 host NOT_INCLUDED、bare/CIDR/wildcard 不变、port 与 anti-rebinding 门照常。域名 URL rule 的 resolved-IP 反检需配对网段(固有语义——域名规则无法仅凭 IP 自证,非 bug)。

## 4. 防回归(本文件随附)

- **R1(测试)**: [test_execution_gates.py](tests/application/test_execution_gates.py) 新增 `test_http_prefixed_scope_runs_through_executor`——`execute_assessment` 全路径 + `include=("http://192.168.2.18:3000/",)` + 无显式 target 的 step(生产形状),断言 COMPLETED 且无 `scope_violation`。
- **R2(linter)**: [lint_forbidden_patterns.py](scripts/lint_forbidden_patterns.py) 新增 **R4**——`def (_host_matches_rule|_host_matches|_target_matches|_domain_matches)` 仅允许出现在 `domain/scope/models.py`;任何新平行 matcher 直接 CI 红。
- **R3(本文档)**: 作者侧镜像,供 field operator 对应 v9.5 文档查阅。

## 5. 升级注意事项(operator)

- v0.6.0/v0.6.1 引入 `core_assessments.control`(alembic `3f91c2a7d504`),**additive + nullable 默认**,v0.6.1 覆盖 v0.6.0 无需额外迁移;从 v0.5.x 直升 v0.6.1 一条 `secopent db upgrade` 即可。
- 升级边界必跑一次 HTTP-form scope 的端到端评估(postmortem v9.5 教训:单测+realism 绿 ≠ e2e 绿)。
- 从 v0.5.x 降级到 v0.6.1 **不是**回滚 v0.5.x——v0.6.1 的修复要求该 matcher 语义,若现场仍在 v0.5.3 且无法立即升级,临时缓解为 bare-host scope(已知精度损失)。
