# v0.3.0 Architecture Refactor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Eradicate the "implicit cross-boundary" bug class (v3 race / v4 lock / v5 leak) at the architecture level: explicit transaction boundaries (UoW), short per-phase transactions, audit off the hot path (Transactional Outbox), BackgroundTasks instead of raw threads, a locked AuditChain, a data-driven assessment state machine, an integration graph PR gate, and a forbidden-pattern linter.

**Architecture:** DDD layering is preserved — `application/` stays storage-agnostic (no SQLAlchemy imports; `session: Any` in Protocols). The Unit of Work lives in infrastructure and is used at the router/daemon boundary; `execute_assessment` keeps its repo-injected signature. Phase commits are done through the already-threaded session (no new parameter threading — v5 lesson). The Outbox replaces only `_audit_record`'s synchronous double-write; permit nonces and request-path audits stay synchronous.

**Tech Stack:** Python 3.12 (`py -3.12`), FastAPI 0.115, SQLAlchemy 2.x, SQLite WAL (PostgreSQL-compatible ORM), alembic, pytest (+ `realism` marker), ruff / mypy --strict / bandit -ll.

**Baseline:** v0.2.0.2 (commit `4018064` + handoff doc `b0fd4dd`). Tests: 1324 passed baseline.

## Design decisions (deviations from handoff-roadmap.md, verified against code)

- **D1 — UoW placement.** Handoff proposed `execute_assessment(db=Database)` with concrete repos inside `application/`. Rejected: breaks all in-memory tests and violates the project's DDD boundary rule. UoW is `Database.unit_of_work()` in `infrastructure/db/session.py`; the router's daemon function uses it; `execute_assessment` keeps repo injection.
- **D2 — Phase commits without new parameters.** New commits happen at phase boundaries via the session already reachable through `getattr(audit_repo, "session", None)` (memory repos → no session → no-op). Zero signature changes → no v5-style incomplete-threading risk.
- **D3 — Outbox scope.** Only `_audit_record` writes an outbox row (worker later fans out to `core_audit_events` + `core_signed_audit_events`). `record_permit_nonce` stays synchronous (replay detection must not be async). Emergency-stop / request-path audits stay synchronous (compliance immediacy). Known trade-off: queryable audit API lags ≤ poll interval (default 1s); signed-chain integrity unaffected.
- **D4 — Outbox startup drain.** On boot, pending outbox rows are drained synchronously BEFORE the app serves, so a crash+restart leaves no permit-replay detection window.
- **D5 — AuditChain lock covers store append.** The lock wraps the entire `record()` body INCLUDING `store.append` — appending outside the lock would allow out-of-order persistence and break `_load_from_store` chain reconstruction on restart.
- **D6 — BackgroundTasks keep the explicit commit.** FastAPI 0.115 runs yield-dependency exit code (the DbSession commit) AFTER background tasks, so the v3 explicit `session.commit()` before `add_task` is kept. The daemon becomes a module-level function with explicit parameters (no closure over `request`/`session`).
- **D7 — State machine = data-driven transition table** (user-confirmed). Enum + frozen `Assessment` aggregate unchanged; a single `ALLOWED_TRANSITIONS` table + one guard method centralize all transitions and fix the two missing guards (`attach_plan`, `approve` currently check no status).
- **D8 — Linter rules are allowlist-based** to avoid false positives on legitimate `open_session` users (SSE polling, recorders, UoW itself).

### UnitOfWork (infrastructure)
```python
class UnitOfWork:
    """Explicit transaction boundary: one UoW = one session = one commit point."""
    def __init__(self, factory) -> None:  # sessionmaker, keeps Database loosely coupled
        self._factory = factory
        self._session: Session | None = None
    def __enter__(self) -> "UnitOfWork":
        self._session = self._factory()
        return self
    def __exit__(self, exc_type, exc_val, exc_tb) -> None:
        assert self._session is not None
        try:
            if exc_type is None:
                self._session.commit()
            else:
                self._session.rollback()
        finally:
            self._session.close()
            self._session = None
    @property
    def session(self) -> Session: ...
    def commit(self) -> None: ...      # explicit phase commit, stays open for next phase

class Database:
    def unit_of_work(self) -> UnitOfWork:   # contextlib.contextmanager or plain class usage
        return UnitOfWork(self._factory)
```
Usage: `with db.unit_of_work() as uow: ...` — commit on clean exit, rollback on exception, always close.

### Router daemon (`_run`)
Replace the manual `bg_session = db.open_session(); try: ... commit(); except: rollback(); finally: close()` with:
```python
with db.unit_of_work() as uow:
    ... build repos on uow.session, execute_assessment(...), ...
# commit/rollback/close are structural now
```
The netns create/destroy and active_executions register/discard stay in the outer try/finally (cleanup must outlive the UoW).

### Phase commits (execution.py)
```python
def _phase_commit(audit_repo: object) -> None:
    """Commit the caller-owned session at a phase boundary (short transactions).

    No-ops for in-memory repos (no session). Releases the SQLite WAL write
    lock before long-running phases so emergency stops / SSE / other writers
    are never blocked for the duration of a scan (v4 root cause).
    """
    session = getattr(audit_repo, "session", None)
    if session is not None:
        session.commit()
```
Commit points (exactly these):
1. after `_check_plan_scope` passes, immediately BEFORE `step_runner = step_runner_factory(scope)` — releases the lock before the multi-minute scan;
2. after the findings-persist loop, BEFORE the oracle block;
3. after the oracle block (success or `oracle.batch_failed` audit), BEFORE `service.complete`;
4. inside `oracle_service._verify_one` epilogue: commit via the same helper semantics after each finding's writes (confirmed + verdict + audits) so the oracle's N×rescan phase never holds the lock across findings. Implementation: `oracle_service` already receives `session`; add a module-level `_commit(session)` there guarded on `session is not None` (same shape, no import from execution.py).

Early-return paths (emergency stop / permit invalid / scope violation) need no explicit commit — `execute_assessment` returns normally and the outer UoW commits them.

### OutboxRecorder (satisfies the AuditRecorder protocol)

```python
class OutboxRecorder:
    def __init__(self, db: Database) -> None: self._db = db
    def record(self, *, actor, action, resource_type, resource_id, payload,
               session=None) -> None:
        row = CoreAuditOutbox(actor=actor, action=action, ..., status="pending",
                              created_at=utc_now())
        if session is not None:
            session.add(row)                    # joins the business tx — atomicity
        else:
            with self._db.unit_of_work() as uow: uow.session.add(row)
```

### OutboxWorker
```python
class OutboxWorker:
    def __init__(self, db, audit_chain, *, poll_interval: float = 1.0) -> None: ...
    def drain_pending(self) -> int:
        """Drain until empty (startup recovery + shutdown flush). Returns count."""
    def run_forever(self) -> None:
        while not self._stop.wait(self._poll_interval): self._drain_batch()
    def stop(self) -> None: self._stop.set()
    def _drain_batch(self) -> None:
        with self._db.unit_of_work() as uow:
            rows = pending rows ORDER BY id LIMIT 100
            for row in rows:
                try:
                    AuditService(SqlAlchemyAuditRepository(uow.session)).record(...)
                    self._audit_chain.record(..., session=uow.session)
                    row.status, row.processed_at = "done", utc_now()
                except Exception as exc:   # keep the chain alive; flag the row
                    row.status, row.error = "failed", str(exc)[:1024]
                    _logger.warning(...)
```
Single worker thread → drain ordering is serialized; chain counter/tail consistency follows from T2's lock. `status='failed'` rows are left for operator inspection (never silently dropped).

### Transition table (the single source of truth)
```python
ALLOWED_TRANSITIONS: Mapping[AssessmentStatus, frozenset[AssessmentStatus]] = {
    DRAFT:             frozenset({AWAITING_APPROVAL}),
    PLANNED:           frozenset(),                    # reserved, currently unreachable
    AWAITING_APPROVAL: frozenset({APPROVED, REJECTED, AWAITING_APPROVAL}),  # re-plan ok
    APPROVED:          frozenset({QUEUED}),
    REJECTED:          frozenset(),                    # terminal
    QUEUED:            frozenset({RUNNING}),
    RUNNING:           frozenset({COMPLETED, PARTIAL, FAILED}),
    PAUSED:            frozenset(),                    # reserved
    COMPLETED:         frozenset(),                    # terminal
    PARTIAL:           frozenset(),                    # terminal
    FAILED:            frozenset(),                    # terminal (restart = new assessment)
    CANCELLED:         frozenset(),                    # terminal
}

def assert_transition(current: AssessmentStatus, target: AssessmentStatus) -> None:
    if target not in ALLOWED_TRANSITIONS[current]:
        raise DomainValidationError(
            f"illegal assessment transition: {current.value} -> {target.value}")
```
Domain layer (no I/O), raises the existing `DomainValidationError` so HTTP mappings don't change.
