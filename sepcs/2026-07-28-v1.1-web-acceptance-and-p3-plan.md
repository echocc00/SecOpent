## 3. P3 Phase B 详细方案（4-6 周 -> v1.1-stable）

### 3.1 默认 TestCatalog 种子（2-3 天）【P3 首要】

**问题**：plan 生成（`POST /assessments/{id}/plans`）取 `catalog.latest_catalog()`，但库空时返回 None -> plan 不可用。当前需操作手手 POST catalog。

**目标**：bundled 默认 catalog，覆盖 OWASP WSTG + CIS 基线，开箱即用。

**实现**：
1. **`src/secopent/infrastructure/catalog/default_catalog.py`**（新建）：
   ```python
   def build_default_catalog() -> TestCatalog:
       """OWASP WSTG + CIS Top 20 映射的默认 TestCatalog（产品 IP 种子）。"""
       classes = (
           TestClass(id="wstg-inpv-01", name="SQL Injection", domain="web",
                     required_tools=("nuclei", "dalfox"), owasp_wstg="WSTG-INPV-01",
                     cis="CIS-3.1"),
           TestClass(id="wstg-inpv-11", name="XSS", domain="web",
                     required_tools=("nuclei", "dalfox"), owasp_wstg="WSTG-INPV-11"),
           # ... 30-50 类，覆盖 Web/API/网络/云四域
       )
       return TestCatalog(version="2026.07-default", classes=frozenset(classes))
   ```

2. **启动钩子**（`main.py create_app`）：若 `catalog.latest_catalog()` 为 None，seed 默认 catalog：
   ```python
   if catalog_repo.latest_catalog() is None:
       catalog_repo.add(build_default_catalog())
   ```

3. **CLI 命令**：`secopent catalog seed --default` / `secopent catalog import <yaml>` 供运维刷新。

4. **覆盖矩阵**：`CoverageMatrix` 映射 catalog classes -> OWASP/CIS 条目（domain 已有，补 seed）。

**验收**：新装实例 `GET /catalog/latest` 返回非空；`POST /assessments/{id}/plans` 生成非空 DAG；CoverageMatrix 显示已覆盖条目。

### 3.2 端到端编排实测（1 周）【P3 核心】

**问题**：单元测试绿，但 Planner -> jobs -> adapter 执行 -> findings -> oracle -> report **全链路在真实靶标上未跑通**。P2-F 覆盖单适配器链；P3 验证编排层。

**目标**：3 类典型渗透流程在 Juice Shop/crAPI/本地 Docker 上端到端跑通。

**流程**（`tests/e2e_real/test_orchestration.py`，新建，`@pytest.mark.e2e_real`）：
```python
def test_full_web_pentest_juice_shop(require_target):
    url = require_target("juice_shop")
    # 1. scope 冻结
    snapshot = ScopeService(...).freeze(draft)
    # 2. catalog + planner 生成 plan
    plan = Planner(...).generate(snapshot, catalog=build_default_catalog())
    assert plan.steps  # 非空 DAG
    # 3. orchestrator 执行（真实 adapter 容器）
    report = Orchestrator(...).execute(plan, snapshot)
    # 4. findings 经 oracle N/N
    confirmed = [f for f in report.findings if f.oracle_verdict == VerificationStatus.CONFIRMED]
    assert confirmed  # Juice Shop 必有 SQLi/XSS
    # 5. CoverageMatrix 覆盖率
    assert report.coverage_rate > 0.3
    # 6. 报告生成 + 三层证据 + 审计链
    rendered = ReportRenderer(...).render(ReportData(...), report_id=...)
    assert AuditChain(...).verify().valid
```

**3 类场景**：
| 场景 | 靶标 | 期望 |
|---|---|---|
| Web 黑盒 | Juice Shop | SQLi/XSS finding CONFIRMED，coverage > 30% |
| API 测试 | crAPI | BOLA finding，Schemathesis 5 类突变 |
| 云资产 | 本地 docker.sock | 容器逃逸/权限 finding |

**关键修复预期**：编排层首次真实跑会暴露 planner-job 衔接、adapter 结果聚合、oracle 触发时机等集成 bug。预留 3-4 天修。

**验收**：3 场景全绿；每场景留 evidence 三层 + 审计链可校验。

### 3.3 LLM 调用点激活与验证（3-4 天）

**现状**：`application/` 有 6 文件引用 ModelBackend（canary/jobs/logic_generator/oracle/orchestrator/planner/remote_model），但需验证 LLM **实际被调用**且边界正确（propose only，never decide）。

**核查与激活**：
1. **AppModel 半自动导入**（§设计 11.6）：从 OpenAPI/Postman 导入时，LLM 提议状态机 + 不变量草稿（`llm_proposed=True`）-> 人审改。验证 `appmodels` 导入端点调 LLM。
2. **POC 草拟**：Case YAML 的 `analyze` 端点，LLM 可草拟 declared risk（当前是规则计算）。验证 LLM 草稿 vs 规则计算双通道。
3. **报告润色**：`ReportRenderer` 的 exec summary，LLM 润色（数字仍来自确定性层）。验证润色不篡改数字。

**边界测试**（`tests/security/test_llm_boundary_e2e.py`，新建）：
- LLM 提议的 AppModel 状态 = `LLM_PROPOSED`（非 SIGNED）
- LLM 草拟的 finding severity 被忽略（severity 由规则/oracle 定）
- LLM 润色的报告数字与确定性层一致（diff 校验）

**验收**：3 个 LLM 调用点实际触发（Mock LLM 验证调用 + 真实 MiniMax 烟测 1 次）；边界测试绿。

### 3.4 知识层真实内容（1 周）

**问题**：intel DB（OSV）+ nuclei-templates 映射当前空/未同步。知识层无内容则检测能力为零。

**实现**：
1. **OSV 同步**（`scripts/sync_intel.py`，新建）：
   ```bash
   py -3.12 -m secopent.scripts.sync_intel --source osv --limit 5000
   ```
   拉 OSV.dev API（中国可用，NVD 503 不可）-> 入 SQLite FTS5。

2. **nuclei-templates 映射**：拉 `nuclei-templates` repo -> 解析 tag -> 映射到 TestCatalog classes（`CurationLagChecker` 真实实现）。

3. **Update Bundle 真实签名**：用 §3.8 的密钥签一个 intel bundle -> staging -> activate -> `GET /updates/active` 返回真实 bundle。

4. **KnowledgeHealthMonitor 真实 checker**：P2-占位 §4.1 接线时，注入真实 `GitFreshnessChecker`（nuclei-templates repo）、`OsvReachabilityChecker`（OSV API ping）。

**验收**：`GET /intel/search?q=sql` 返回真实 CVE；`GET /updates/health` 4 检测器真实状态；`GET /updates/active` 真实 bundle。

### 3.5 性能（3-4 天）

1. **SQLite WAL**：`create_sqlite_engine` 已开 WAL（核查）；补 `PRAGMA synchronous=NORMAL` + `journal_size_limit`。大评估（>1000 findings）查询加索引。
2. **SSE 背压**：当前 demo 无背压。真实化时（P2-占位 §4.6）用 `asyncio.Queue` 限流，丢慢客户端。
3. **Plan DAG 渲染**：>50 节点的 plan，react-flow 用 `useReactFlow().fitBounds()` + 虚拟化。补性能测试。
4. **adapter 执行吞吐**：`SubprocessExecutor` 当前串行。加 `--parallel N`（JobService lease 机制已支持并发，补 executor 并发）。

**验收**：1000 findings 列表 < 500ms；50 节点 DAG 渲染 < 1s；3 并发 adapter 不死锁。

### 3.6 Monaco chunk 优化（1 天）

**问题**：CaseStudio chunk 683 KB gzip（Monaco 全量）。

**方案**（`YamlEditor.tsx`）：
1. 用 `monaco-editor/esm/vs/editor/editor.api` 核心 + 仅注册 yaml 语言：
   ```typescript
   import * as monaco from "monaco-editor/esm/vs/editor/editor.api";
   import "monaco-editor/esm/vs/basic-languages/yaml/yaml.contribution";
   ```
2. 去掉 JSON/HTML/TS 等未用语言包 -> 预期 chunk 降到 ~300 KB gzip。
3. 或：生产用 CDN + SRI（`loader.config({ paths: { vs: "https://cdn.jsdelivr.net/npm/monaco-editor@x/min/vs" } })`），dev 本地。二选一。

**验收**：CaseStudio chunk < 350 KB gzip；YAML 高亮+校验可用。
