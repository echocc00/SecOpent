## T3: v4 root-cause fix — full same-transaction refactor

**Why third:** v4's actual root cause is the cross-connection double-write: `_audit_record` writes to `core_audit_events` via the daemon's `bg_session` AND to `core_signed_audit_events` via the store's own per-event connection. The full refactor merges both writes into the **same session** (the daemon's `bg_session`), so every audit event = 1 transaction, 1 WAL frame, 1 commit. No cross-connection contention. The `busy_timeout=60s` from T2 becomes belt-and-suspenders.

**Scope of this refactor (5 sub-tasks):**
- T3.1: `SqlAlchemySignedAuditEventStore.append` accepts `session=` (no commit when provided)
- T3.2: `SqlAlchemyAuditRepository` exposes a `.session` property (the bound session)
- T3.3: `AuditChain.record` accepts `session=` and passes it to the store
- T3.4: `_audit_record` in `execute_assessment.py` refactored to take `audit_repo` + `audit_chain` and write both tables via the same session
- T3.5: Remove the local `audit = AuditService(audit_repo)` shadowing in `execute_assessment:279`; pass `audit_repo` to `_audit_record`; the `bg_session` is committed once at the end of `_run` and persists BOTH audit tables atomically

**Known caveat (documented, not blocking):** `AuditChain`'s in-memory state (`_counter`, `_tail`, `_events`) is **not thread-safe** — `record()` does `_counter += 1` then `event_id=f"evt-{self._counter}"`, which races under concurrent threads. This is by design: the chain is used by the daemon (single thread). v0.2.0.1 leaves this as-is; v0.3.0 may add a `threading.Lock` if peer-agent or other concurrent recorders become a goal. The realism test (T5) uses single-threaded recording, so this is not exercised.

```python
    db = create_sqlite_engine(tmp_path / "t.db")

    chain = AuditChain(AuditKeyManager(), store=store)

    chain.record(actor="t", action="t", resource_type="t", resource_id="t",
                 payload={})
    with db.open_session() as session:
        # Spy on commit/open_session via the session itself.
        commits = []
        orig_commit = session.commit
        session.commit = lambda: commits.append(1) or orig_commit()
        # Append a second event with the EXTERNAL session.
        ev = chain.events()[-1]

        chain.record(actor="t2", action="t2", resource_type="t2",
                     resource_id="t2", payload={}, session=session)
        # session.commit was NOT called by the store (only by us if/when we commit).
        assert commits == [], "store must NOT commit when session provided"

    with db.open_session() as verify:
```

### T3.4: `_audit_record` refactored to merge into one session

**File:** `src/secopent/application/execution.py`, function `_audit_record` (around line 113)

Change signature from `(audit: AuditService, audit_chain: AuditChain | None, *, ...)` to `(audit_repo: SqlAlchemyAuditRepository, audit_chain: AuditChain | None, *, ...)`. Body writes both via `audit_repo.session`:

```python
def _audit_record(
    audit_repo: SqlAlchemyAuditRepository,
    audit_chain: AuditChain | None,
    *,
    actor: str,
    action: str,
    resource_type: str,
    resource_id: str,
    payload: dict[str, object],
    permit_nonce: str | None = None,
) -> None:
    """Record to the DB audit AND the signed chain in the SAME transaction
    (v4 refactor). The caller (execute_assessment) commits the shared session
    once at the end of _run, persisting both tables atomically.

    # Write 1: core_audit_events (via the repo, same session).
    audit_repo.add(AuditEvent.create(
        event_id=f"pending-{uuid.uuid4().hex[:12]}",  # placeholder; real
            # id assigned after hash chain appends
        actor=actor, action=action, resource_type=resource_type,
        resource_id=resource_id, payload=dict(payload),
        previous_hash="",  # overwritten below
    ))  # NOTE: this add is a placeholder — the actual flow uses
    # audit_chain.record which builds the event with proper hash chain prev_hash.
    # See T3.4 implementation note below.
```

**T3.4 implementation note (this is the tricky bit):** `_audit_record` currently calls `audit.record(...)` (the AuditService), which internally:
1. Builds the `AuditEvent` (with `previous_hash` from the chain's `_tail`)
2. Calls `repo.add(event)` (adds to session)
3. Returns the event

But the signed chain needs the **same** event (with the same hash) to sign and persist. Currently, the old `AuditService` builds the event, then the chain builds a SEPARATE event (with its own counter and prev_hash). So the two tables hold different events (different ids, different hashes).

This is a pre-existing design flaw exposed by the refactor: the `core_audit_events` row and the `core_signed_audit_events` row have **different event_ids and different event_hashes**. The "signed" chain signs an event different from the one stored in `core_audit_events`. The audit chain's hash chain is over the SIGNED events, not the audit_events.

This is actually... by design? The v3-C docstring says: "Distinct from `core_audit_events` (the M0 queryable audit log, no signature): `core_signed_audit_events` stores the Ed25519-signed hash chain so tamper-evidence survives process restart." So they are intentionally separate streams: the M0 queryable log + the signed tamper-evident chain. Different event_ids are expected.

OK so the refactor's correctness is: write to BOTH tables in the SAME session, with the chain's event (the signed one) going to `core_signed_audit_events` AND a separate event (the queryable log) going to `core_audit_events`. The two events are different (different ids, different hashes) by design. They just need to be in the same transaction so they commit atomically.

So the refactored `_audit_record`:
1. Write the queryable log event to `core_audit_events` via `audit_repo.add(event1)` (session = audit_repo.session).
2. Write the signed chain event to `core_signed_audit_events` via `audit_chain.record(..., session=session)` (which calls `store.append(signed, session=session)`).

Both in the same `session`. The caller's `bg_session.commit()` persists both atomically.

```python
def _audit_record(
    audit_repo: SqlAlchemyAuditRepository,
    audit_chain: AuditChain | None,
    *,
    actor, action, resource_type, resource_id, payload, permit_nonce=None,
) -> None:
    """Record the queryable log + the signed chain in the SAME transaction
    (v4 refactor). The caller commits the shared session once.
    """
    session = audit_repo.session
    # 1) Queryable audit log (M0): AuditEvent with a fresh id (not chained).
    #    The audit chain (M3-C) maintains its own counter + hash chain; the
    #    two streams are intentionally separate. We only need them atomic.
    audit_repo.add(AuditEvent.create(
        event_id=f"evt-{uuid.uuid4().hex[:12]}",
        actor=actor, action=action, resource_type=resource_type,
        resource_id=resource_id, payload=dict(payload),
        previous_hash="",  # unused for the queryable log
    ))
    # 2) Signed chain (M3-C): builds its own AuditEvent with hash chain
    #    prev_hash, signs it, appends to core_signed_audit_events via the
    #    SAME session. No commit (the store does NOT commit when session
    #    is provided — T3.1).
    if audit_chain is not None:
        audit_chain.record(
            actor=actor, action=action, resource_type=resource_type,
            resource_id=resource_id, payload=dict(payload),
            permit_nonce=permit_nonce, session=session,
        )
```

Hmm wait — the `previous_hash` for the queryable log: currently `AuditService.record` computes it from the chain (the audit_repo's `last_hash()`). Let me check. From application/audit.py: `previous = self._repo.last_hash() or GENESIS_HASH`. So it uses the chain's last hash (from `core_audit_events`, not the signed chain). The queryable log has its OWN chain (a simpler hash chain over core_audit_events). The signed chain is a SEPARATE chain.

So the queryable log (`core_audit_events`) has a hash chain over itself (prev_hash from the last core_audit_events row). The signed chain (`core_signed_audit_events`) has its own hash chain (prev_hash from the last core_signed_audit_events row). Two independent hash chains, two independent event sequences.

OK so my refactored `_audit_record` needs to preserve BOTH hash chains. The `audit_repo.add` for the queryable log uses the audit_repo's `last_hash()` (chain over core_audit_events). The `audit_chain.record` uses its own `_tail` (chain over core_signed_audit_events).

So the refactored function should be:

```python
def _audit_record(audit_repo, audit_chain, *, actor, action, ...):

        resource_id=resource_id, payload=dict(payload),
    )  # adds to session; AuditService does repo.add with chain
    # 2) Signed chain (uses audit_chain's own counter + hash chain)
    if audit_chain is not None:
        audit_chain.record(
            actor=actor, action=action, resource_type=resource_type,
            resource_id=resource_id, payload=dict(payload),
            permit_nonce=permit_nonce, session=session,
```

```python
"""v4 regression: high-frequency signed audit must not lock."""
from __future__ import annotations

import threading

import pytest

from secopent.application.audit_chain import AuditChain
from secopent.infrastructure.audit.key_manager import AuditKeyManager
from secopent.infrastructure.db.sqlite import create_sqlite_engine
from secopent.infrastructure.repositories.sqlalchemy_audit_chain import (
    SqlAlchemySignedAuditEventStore,
)


@pytest.mark.realism
def test_concurrent_audit_writers_no_operational_error(tmp_path) -> None:
    """N threads each record M events; none should fail with database is locked."""
    db = create_sqlite_engine(tmp_path / "storm.db")
    store = SqlAlchemySignedAuditEventStore(db)
    chain = AuditChain(AuditKeyManager(), store=store)
    errors: list[Exception] = []

    def worker(thread_id: int, count: int) -> None:
        try:
            for i in range(count):
                chain.record(
                    actor=f"t{thread_id}", action="a",
                    resource_type="r", resource_id=f"r{i}",
                    payload={"thread": thread_id, "i": i},
                )
        except Exception as e:  # noqa: BLE001
            errors.append(e)

    threads = [
        threading.Thread(target=worker, args=(t, 50))
        for t in range(4)
    ]
    for t in threads: t.start()
    for t in threads: t.join()
    assert not errors, f"audit storm failed: {errors[:3]}"
```
