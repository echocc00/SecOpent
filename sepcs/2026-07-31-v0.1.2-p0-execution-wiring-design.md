## 1. 设计

### 1.1 状态流
```
APPROVED --POST /start--> QUEUED --后台 mark_running--> RUNNING --完成--> COMPLETED
                                                      \--失败--> FAILED
                       POST /stop (紧急) --> CANCELLED
```

### 1.2 AssessmentService 补 4 方法（`application/assessments.py`）
```python
def start(self, assessment_id: str, *, actor_role: str = "human") -> Assessment:
    """APPROVED -> QUEUED. Human-only (triggers real scans)."""
    self._require_human(actor_role)
    a = self._get(assessment_id)
    if a.status is not AssessmentStatus.APPROVED:
        raise DomainValidationError(f"cannot start from {a.status}")
    if not a.active_plan_id:
        raise DomainValidationError("assessment has no plan")
    return self._save(a.start(plan_id=a.active_plan_id, approval_id=a.approval_id))

def mark_running(self, assessment_id: str) -> Assessment:
    """QUEUED -> RUNNING (called by background executor)."""
    a = self._get(assessment_id)
    return self._save(replace(a, status=AssessmentStatus.RUNNING))

def complete(self, assessment_id: str) -> Assessment:
    """RUNNING -> COMPLETED."""
    a = self._get(assessment_id)
    return self._save(replace(a, status=AssessmentStatus.COMPLETED))

def fail(self, assessment_id: str, reason: str) -> Assessment:
    """RUNNING -> FAILED."""
    a = self._get(assessment_id)
    return self._save(replace(a, status=AssessmentStatus.FAILED))
```

### 1.3 后台执行函数（`application/execution.py`，新建）
```python
def execute_assessment(*, app: FastAPI, assessment_id: str) -> None:
    """后台线程：构造 Orchestrator -> 跑到完成 -> 聚合 findings -> 更新状态。

    在 daemon 线程中运行（单用户本地场景足够）。SSE 轮询 status 推送进度。
    """
    db = app.state.db
    session = db.open_session()
    try:
        repo = SqlAlchemyAssessmentRepository(session)
        service = AssessmentService(repo)
        service.mark_running(assessment_id)            # QUEUED -> RUNNING

        assessment = repo.get(assessment_id)
        plan = repo.get_plan(assessment.active_plan_id)
        scope = SqlAlchemyScopeRepository(session).get_snapshot(assessment.scope_snapshot_id)

        # 构造执行上下文（targets 从 scope.include 提取）
        targets = tuple(url for url in scope.include)
        scan_runner = RealScanRunner(default_timeout=180)
        step_runner = AdapterStepRunner(scan_runner, ScanContext(targets=targets))

        # Orchestrator 跑到完成
        jobs = JobService()
        for step in plan.steps:
            jobs.add(Job.from_plan_step(step, assessment_id=assessment_id))
        Orchestrator(jobs, step_runner).run_to_completion(owner="system", now=utc_now())

        # 聚合 findings（关联 assessment_id）
        observations = [o for j in jobs.all() for o in step_runner.observations_for(j.step_key)]
        findings = FindingCorrelator().correlate(observations)
        finding_repo = SqlAlchemyFindingRepository(session)
        for f in findings:
            finding_repo.add(replace(f, assessment_id=assessment_id))

        service.complete(assessment_id)                # RUNNING -> COMPLETED
        AuditService(SqlAlchemyAuditRepository(session)).record(
            actor="system", action="assessment.completed",
            resource_type="assessment", resource_id=assessment_id,
            payload={"findings": len(findings)})
    except Exception as exc:                           # noqa: BLE001
        service.fail(assessment_id, str(exc))
        AuditService(...).record(actor="system", action="assessment.failed",
                                 resource_type="assessment", resource_id=assessment_id,
                                 payload={"reason": str(exc)})
    finally:
        session.close()
```

**注意**：`Job.from_plan_step` / `step_runner.observations_for` 可能不存在 -- 需核查 T5 的实际 API 并对齐命名（T5 用 `Orchestrator.dispatch` 创建 jobs，可能不需手动 `jobs.add`；`observations_for` 可能叫别的）。dev model 实现时按 T5 真实签名调整。

### 1.4 API 端点（`interfaces/api/routers/assessments.py`）
```python
@router.post("/{assessment_id}/start", response_model=AssessmentOut)
def start_assessment(
    assessment_id: str, payload: StartRequest, request: Request, session: DbSession
) -> AssessmentOut:
    """Trigger execution: APPROVED -> QUEUED, spawn background executor."""
    service = AssessmentService(SqlAlchemyAssessmentRepository(session))
    try:
        assessment = service.start(assessment_id, actor_role=payload.actor_role)
    except DomainValidationError as exc:
        raise HTTPException(status_code=422, detail=str(exc)) from exc
    # 后台执行（daemon 线程，立即返回）
    import threading
    threading.Thread(
        target=execute_assessment,
        kwargs={"app": request.app, "assessment_id": assessment_id},
        daemon=True,
    ).start()
    return _to_out(assessment)
```

`StartRequest` schema（`schemas.py`）：`actor_role: str = "human"`（human-only，LLM 边界）。

## 2. 边界与安全

- **actor_role 强制**：`start` 是 human-only（触发真实扫描，agent 不可）。复用 `_require_human`。
- **状态守卫**：`start` 仅 APPROVED 可调；`mark_running` 仅 QUEUED；`complete/fail` 仅 RUNNING。防重复触发。
- **并发**：单 assessment 同时只一个执行（status 守卫保证）。单用户本地无需分布式锁。
- **紧急停止**：`POST /stop`（T11 已有）设 `app.state.emergency_stop` 标志；后台线程在每步前检查（Orchestrator 的 dispatch 循环加 check 点）。
- **审计**：start/completed/failed 全记审计链。
